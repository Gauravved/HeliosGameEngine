# Event Subsystem

> Status: ✅ Completed

---

# Purpose

The Event Subsystem provides a platform-independent mechanism for delivering user and window events throughout the engine.

Instead of allowing every subsystem to directly communicate with the platform layer (Win32), events are generated by the platform and propagated through the engine using a common Event interface.

This keeps the engine modular, platform-independent, and easy to extend.

---

# Responsibilities

The Event Subsystem is responsible for:

- Keyboard events
- Mouse events
- Mouse movement
- Mouse scrolling
- Window resize
- Window close
- Event propagation
- Event dispatching

---

# Architecture

```
Win32 Window Procedure
          │
          ▼
    Create Event Object
          │
          ▼
WindowsWindow::SetEventCallback()
          │
          ▼
Application::OnEvent()
          │
          ▼
EventDispatcher
          │
          ▼
Individual Layers
```

# Design Decisions

## Why use an Event Base Class?

Every event shares common functionality.

Examples:

- Event Type
- Event Category
- Handled State

Using inheritance allows all events to be treated uniformly while still storing event-specific data.

---

## Why EventDispatcher?

Without a dispatcher every listener would need to manually check every event type.

Instead we can write

```cpp
dispatcher.Dispatch<KeyPressedEvent>(...);
```

The dispatcher performs type checking internally.

This keeps the code clean and scalable.

---

## Why Event Categories?

Some systems care about a specific event.

Example:

```
WindowResizeEvent
```

Other systems only care about a category.

Example:

```
Any Keyboard Event
```

Categories make filtering extremely simple.

---

## Event Lifetime

Events are created by the platform layer.

They exist only while being propagated through the engine.

No subsystem owns an event permanently.

This avoids unnecessary allocations and ownership complexity.

# Lessons Learned

- Platform-specific code should never leak into engine systems.
- Events represent something that already happened.
- Events are transient objects and should not own long-lived state.
- EventDispatcher removes repetitive type checking while remaining type-safe.
